# Требования к MeshVault и зависимости

Статус: рабочий черновик. Документ фиксирует, что программа обязана делать, на чём она работает, какие внешние компоненты нужны и какие из них можно убрать без потери ядра.

## 1. Назначение

MeshVault — локальный каталог 3D-моделей с просмотром, подготовкой и отправкой на печать. Сервер хранит авторитетную базу и файлы; клиент показывает библиотеку, 3D-превью и управляет печатью через Moonraker.

## 2. Границы

- Развёртывание: один ПК или домашний сервер в локальной сети.
- Режим: сейчас одно-пользовательский; многопользовательский режим не реализован.
- Интернет не обязателен: нужен только доступ к принтеру в LAN.
- Облачная синхронизация, аккаунты и публичный доступ не входят в текущую область.

## 3. Функциональные требования

### FR-01. Загрузка и форматы
- Приём файлов через API/десктоп-клиент.
- Поддержка: STL, 3MF, OBJ, GLB/glTF, PLY, AMF, STEP/STP, IGES/IGS, G-code/BGCode, LYS.
- Лимит загрузки по умолчанию 512 МБ (`MESHVault_MAX_UPLOAD_MB`).

### FR-02. Хранение и дедупликация
- Оригиналы неизменяемы.
- Content-addressed хранилище: `data/blobs/<aa>/<bb>/<sha256>`.
- Повторная загрузка того же содержимого не создаёт дубликат блоба.
- В SQLite только метаданные и ссылки.

### FR-03. Обработка версии
- Фоновая обработка после загрузки/импорта.
- Производные: GLB для просмотра, PNG-миниатюра.
- Метрики: габариты, объём, число треугольников, замкнутость, единицы.
- Статусы: `processing`, `ready`, `failed`; ошибка сохраняется в версии.
- При рестарте сервера зависшие `processing` переводятся в `failed`.

### FR-04. Библиотека
- Список моделей, поиск, теги, коллекции.
- Карточка модели, версии, скачивание оригинала/производных.
- Редактирование названия/описания/тегов/коллекций, удаление.

### FR-05. 3D-просмотр
- Qt Quick 3D загружает нормализованный GLB.
- Вращение/масштаб, тёмная тема, локальный кэш GLB на клиенте.

### FR-06. Автоимпорт
- Рекурсивное сканирование настроенного каталога.
- Теги из имён вложенных папок и расширения; верхняя папка — коллекция.
- Пропуск уже импортированных файлов и дубликатов по sha256.
- Ручной запуск и периодическое сканирование (`MESHVault_IMPORT_INTERVAL_MIN`).

### FR-07. Принтеры
- CRUD принтеров Moonraker: имя, хост, API-ключ, профиль стола.
- API-ключ шифруется в БД и не возвращается клиенту.
- Проверка доступности принтера.

### FR-08. Печать
- Загрузка готового G-code на Moonraker, запуск, пауза/возобновление/отмена.
- Статус, прогресс, история заданий.
- Отказ печати, если у версии нет G-code.
- Серверный слайсинг не используется: модель отправляется во внешний установленный слайсер («Открыть в слайсере»).

### FR-09. Настройки и диагностика
- Адрес сервера и токен в клиенте.
- Настройки импорта в клиенте.
- `/api/health`: статус, версия, форматы, доступность CAD/слайсера, необходимость авторизации.

### FR-10. Авторизация
- Опциональный Bearer-токен (`MESHVault_API_TOKEN`).
- Без токена API открыт в пределах доверенной сети.

### FR-11. Экспорт форматов
- Конвертация версии модели в STL/OBJ/GLB/PLY/3MF через API и клиент.

### FR-12. Корзина
- Мягкое удаление (`deleted_at`), просмотр корзины, восстановление, окончательное удаление.

### FR-13. Printability
- Проверка замкнутости, нависаний, масштаба/единиц и соответствия столу выбранного принтера.

### FR-14. Пакетная загрузка
- Drag&drop нескольких файлов в Qt-клиенте, загрузка очереди файлов.

## 4. Нефункциональные требования

### NFR-01. Платформа
- Сервер: Windows 10/11 x64 — проверенная конфигурация; Linux/macOS возможны при наличии Python и зависимостей.
- Десктоп-клиент: Windows, Qt 6.8+ (проверено на Qt 6.10.3, MSVC 2022).
- Python: 3.10+; текущая venv — 3.15.2. Для extra `cad` может потребоваться версия Python, поддерживаемая CadQuery/OCP.

### NFR-02. Ресурсы
- CPU: x64, 2+ ядра рекомендуется.
- RAM: 4 ГБ минимум; 8 ГБ+ рекомендуется при FreeCAD и больших моделях.
- Диск: ~1 ГБ на окружение/клиент + объём библиотеки и производных файлов.
- GPU: для Qt Quick 3D нужен Direct3D 11/OpenGL 3.3+; серверу GPU не требуется.

### NFR-03. Производительность
- Список/поиск должны оставаться отзывчивыми на тысячах моделей.
- Обработка тяжёлых файлов не блокирует API.
- Миниатюры и GLB — best-effort: отсутствие внешнего рендера не должно ломать импорт.

### NFR-04. Надёжность и данные
- SQLite WAL, атомарная запись блобов через временные файлы.
- Ошибки обработки фиксируются, а не теряются.
- Резервное копирование: каталог `data/` целиком (БД + блобы).
- Внешние инструменты опциональны там, где есть fallback.

### NFR-05. Безопасность
- Секреты принтеров шифруются (`MESHVault_SECRET_KEY`).
- Токен и ключи не попадают в ответы API.
- CORS ограничен настроенными origin.
- Для доступа вне localhost обязателен токен и HTTPS/VPN на уровне сети.

### NFR-06. Лицензии внешних компонентов
- Qt — LGPLv3/GPLv3/коммерческая.
- FreeCAD — LGPL-2.1-or-later.
- CadQuery — Apache-2.0; OCCT — LGPL-2.1 с исключением.
- CuraEngine, PrusaSlicer/OrcaSlicer — AGPL-3.0.
- Moonraker — GPL-3.0.
- Лицензия самого MeshVault пока не зафиксирована — открытый вопрос.

## 5. Матрица зависимостей

### 5.1. Обязательные для ядра
| Зависимость | Тип | Назначение | Можно убрать? |
|---|---|---|---|
| Python 3.10+ | runtime | сервер | нет |
| FastAPI + uvicorn | Python | HTTP API | нет |
| SQLAlchemy + SQLite | Python/встроенная БД | метаданные | нет без переписывания storage |
| pydantic-settings | Python | конфигурация | нет |
| python-multipart | Python | загрузка файлов | нет |
| httpx | Python | Moonraker/тесты | только вместе с печатью/тестами |
| trimesh + numpy | Python | чтение мешей, метрики, GLB | нет для mesh-форматов |
| networkx + lxml | Python | экспорт 3MF | только если убрать 3MF-экспорт |
| Pillow | Python | PNG-заглушка миниатюр | можно сделать опциональной |
| cryptography | Python | шифрование API-ключей | только если убрать хранение ключей |
| Qt 6.8+ | runtime клиента | десктоп UI и 3D | только при переходе на web-клиент |

### 5.2. Опциональные внешние программы
| Программа | Назначение | Обязательна? | Что без неё |
|---|---|---|---|
| FreeCAD | STEP/IGES → STL | нет | STEP через CadQuery; IGES недоступен |
| CadQuery (`extra cad`) | STEP без FreeCAD | нет | STEP требует FreeCAD |
| GUI-слайсер (PrusaSlicer/Orca/Cura/Flashforge) | «Открыть в слайсере» | нет | кнопка отправки в слайсер недоступна |
| Moonraker | печать на Klipper | только для печати | библиотека/просмотр работают |

### 5.3. Только для сборки/разработки
- MSVC Build Tools, CMake, Ninja — сборка Qt-клиента.
- pytest, ruff — тесты/линт.
- Git — версионирование.
- `uv` — управление окружением.

## 6. Можно ли уменьшить зависимости?

Да. Ядро уже не требует внешних исполняемых файлов для mesh-форматов.

### 6.1. Что уже опционально
- **Миниатюры/GLB:** полностью встроены (trimesh + Pillow), внешние рендеры не нужны.
- **FreeCAD:** STEP может идти через CadQuery; IGES требует CAD-ядро.
- **Слайсер:** сейчас не используется; печать принимает готовый G-code.
- **Moonraker:** нужен только для печати.

### 6.2. Профили установки
| Профиль | Состав | Возможности |
|---|---|---|
| Минимальный | Python-сервер + Qt-клиент | STL/3MF/OBJ/GLB/PLY/AMF, библиотека, просмотр, экспорт, корзина, printability, placeholder-миниатюры, печать готового G-code |
| Стандартный | + FreeCAD | STEP/IGES |
| Полный | + GUI-слайсер | отправка модели в слайсер одним кликом |
| Headless/API | только сервер | автоматизация/интеграции; web-клиент пока не реализован |

### 6.3. Направления сокращения
1. **Миниатюры без внешних программ — готово.** Встроенный генератор на Pillow рисует силуэт/каркас и подпись; дальше можно улучшать проекцией реальной геометрии через numpy+Pillow. Новые зависимости не нужны.
2. **STEP без FreeCAD.** Оставить/развивать extra `cad` (CadQuery/OCP). Это убирает внешнюю программу, но увеличивает Python-окружение и не покрывает IGES.
3. **IGES без CAD-ядра.** Практически невозможно без потери функции. Разумный компромисс: при отсутствии FreeCAD/CadQuery просить экспорт в STL/3MF.
4. **Слайсинг.** Серверный слайсинг не планируется. Вместо него — отправка модели в любой установленный GUI-слайсер. Это убирает тяжёлую серверную зависимость и оставляет выбор слайсера за пользователем.
5. **Печать.** Moonraker обязателен для Klipper. Можно добавить OctoPrint/Prusa Connect адаптеры, но какой-то printer API всё равно нужен.
6. **Qt-клиент → web-клиент.** Уберёт установку Qt у пользователя, но потребует разработки `apps/web` (сейчас каталог пуст) и браузера. Десктоп остаётся для нативного 3D.
7. **uvicorn[standard] → uvicorn.** Для production можно убрать лишние extras (watchfiles/websockets), если не нужен `--reload`.
8. **Pillow/cryptography.** Теоретически заменяемы (SVG-заглушка, OS keyring/DPAPI), но выигрыш мал, а кроссплатформенность/сложность растут. Не приоритет.

### 6.4. Что нельзя убрать без потери ядра
- Python, FastAPI/uvicorn, SQLAlchemy/SQLite — сервер и хранение.
- trimesh/numpy — чтение и анализ mesh-форматов.
- Qt — текущий десктоп-клиент.
- Moonraker — печать на Klipper.
- CAD-ядро (FreeCAD или CadQuery/OCP) — STEP/IGES.

## 7. Проверка требований

- `cd server && .venv\Scripts\python.exe -m pytest -q`
- `GET /api/health` → `status=ok`, поля `cad`, `slicer`.
- Загрузка STL без FreeCAD → `ready`, встроенная PNG-миниатюра.
- Загрузка STEP/IGES с FreeCAD → `ready`, корректные габариты.
- Печать версии без G-code → HTTP 400.
- Повторная загрузка того же файла → дедупликация по sha256.
